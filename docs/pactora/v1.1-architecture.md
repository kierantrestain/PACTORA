# PACTORA 1.1 architecture: accounts, email and settings

This is the shared contract for the 1.1 work. Each area has one owner; the
interfaces below are what the others build against. Change an interface
only by updating this file in the same commit.

## 1. Owner provisioning and registration (lead)

`src/lib/owner-provisioning.ts`

```ts
export type OwnerProvisioningMode =
  // Token-free: the first person to register on an empty database becomes
  // the owner. Only where every request already passes an access gate.
  | { mode: "first-owner-open"; reason: "local" | "access-protected" }
  // A public deployment with an empty database: nobody can claim it from
  // the web. The owner is created with `npm run owner:provision` (database
  // credentials) or with OWNER_PROVISIONING_TOKEN.
  | { mode: "provisioning-required"; tokenAccepted: boolean };

export function resolveOwnerProvisioning(env?: EnvSource): OwnerProvisioningMode;

export type RegistrationView =
  | { view: "first-owner" }              // empty DB, token-free first owner
  | { view: "provisioning-required" }    // empty DB on a public deployment
  | { view: "standard"; signupRule: string | null } // owner exists, open/domains
  | { view: "invitation-only" }          // sign-up closed: invitations only
  | { view: "unavailable"; reason: "no_database" | "unmigrated" };

export async function getRegistrationView(): Promise<RegistrationView>;
```

Access protection is asserted by the operator with
`PACTORA_ACCESS_PROTECTED=1` (Vercel Authentication, a VPN, an SSO proxy).
Local development (`next dev`, or a production build on localhost) counts as
protected. `HOSTED_MODE` never allows the open claim.

`POST /api/register` — first-owner registration only.
Body `{ name, email, password }`. 201 `{ redirectTo: "/dashboard" }` (signed
in, verified, role `admin`, workspace named after the owner). 409
`{ code: "owner_exists" }` when someone else won: the client continues with a
normal sign-up. 403 `{ code: "provisioning_required" }` on public
deployments. No support address, sender domain or token is asked for.

Every later account signs up through Better Auth (`authClient.signUp.email`)
under the workspace's sign-up rule, with role `user`.

Sign-in with Google and Microsoft uses Better Auth social providers, enabled
only when `GOOGLE_CLIENT_ID`/`GOOGLE_CLIENT_SECRET` and
`MICROSOFT_CLIENT_ID`/`MICROSOFT_CLIENT_SECRET` are set. The pages receive
`oauthProviders: { google: boolean; microsoft: boolean }` from
`getOAuthLoginProviders()` in `src/lib/auth/oauth-providers.ts`. Login scopes
are `openid email profile` only: signing in never grants mailbox access.

## 2. Invitations (lead)

`src/lib/invitations.ts`, table `workspace_invitations`.

- `GET /api/workspace/invitations` (admin) →
  `{ invitations: InvitationView[] }`
- `POST /api/workspace/invitations` (admin) `{ email, role: "user" | "admin" }`
  → 201 `{ invitation: InvitationView, link: string, emailed: boolean, emailError: string | null }`
- `DELETE /api/workspace/invitations/[id]` (admin) → 204
- `GET /api/invitations/[token]` (public) →
  `{ email, organizationName, inviterName, role, expiresAt, accountExists }`
- `POST /api/invitations/[token]/accept` `{ name, password }` for a new
  account, or `{}` when signed in as the invited address → `{ redirectTo }`.
  The link proves the address, so the account starts verified.

```ts
type InvitationView = {

  invitedByName: string | null; createdAt: number; expiresAt: number;
  status: "pending" | "accepted" | "expired" | "revoked";
};
```

## 4. Universal email engine (email specialist)

`src/lib/email/` behind the existing `EmailService` interface in
`src/lib/services/email.ts`, so every existing caller keeps working.

### Streams

- **platform**: `email_verification`, `password_reset`,
  `change_email_confirmation`, `workspace_invitation`,
  `account_closure_request`, `contact_form`, `signing_lock_alert`.
  Resolved: platform transport from the environment (`RESEND_API_KEY`, or
  `PLATFORM_SMTP_URL`), else capture in development, else the workspace's
  default organisation account, else "not connected".
- **agreement**: everything else. Resolved per message: the sender's
  preferred account (when they may use it and it is connected), else the
  workspace default organisation account, else the legacy environment
  Resend configuration, else capture in development, else "not connected".

`TransactionalEmailMessage` gains optional `envelopeId` and `senderUserId`;
the router finds the sender from the envelope when only `envelopeId` is
given. `test_email` takes an explicit `accountId`.

### Adapters

```ts
interface EmailTransport {
  readonly provider: "gmail" | "microsoft" | "smtp" | "resend" | "capture";
  readonly maxAttachmentBytes: number;
  send(message: OutgoingMessage): Promise<{ providerMessageId?: string }>;
}
```

Gmail API (`users.messages.send`, scope `gmail.send`), Microsoft Graph
(`/me/sendMail`, scope `Mail.Send offline_access`), SMTP (nodemailer, TLS
required, SSRF and DNS-rebinding safe: the address is resolved once, checked
against private ranges, and dialled by IP with SNI/certificate checks on the
host name), Resend (optional), capture (development and tests). A new
provider implements `EmailTransport` and registers a preset.

### Data

- `email_accounts`: owner (`organization` or `personal` + `owner_user_id`),
  provider, preset, address, display name, reply-to, status, encrypted
  credentials (AES-256-GCM, key from `EMAIL_CREDENTIALS_KEY` or HKDF of
  `BETTER_AUTH_SECRET`), non-secret SMTP host/port/security/username,
  provider account id, `is_default`, `shared_with` (`nobody` | `everyone` |
  `teams`), last success, last error.
- `email_account_teams`, `email_account_preferences` (user → account).
- `email_oauth_states`: state, PKCE verifier (encrypted), user, preset,
  scope, expiry (10 minutes), single use.
- `email_deliveries`: idempotency key, stream, account, template, recipient,
  subject, envelope, status (`sent`, `failed`, `retrying`, `deferred`,
  `superseded`), attempts, next attempt, error and recovery text, provider
  message id. The payload for a pending retry is stored encrypted and erased
  once sent or given up.
- `email_templates`: editable subject and opening paragraph for
  `signing_invitation`, `automatic_reminder`, `manual_nudge`,
  `completion_notification`, `workspace_invitation`.

### HTTP API (consumed by Settings > Email & Integrations)

- `GET /api/email/providers` → `{ providers: ProviderOption[] }`
- `GET /api/email/accounts` → `{ accounts: EmailAccountView[], preferredAccountId, canManageOrganization, platformSender: { description: string, accountId: string | null } }`
- `POST /api/email/accounts` (SMTP, Resend) — verifies before saving
- `PATCH /api/email/accounts/[id]` `{ displayName?, replyTo?, isDefault?, sharedWith?, teamIds?, password? }`
- `DELETE /api/email/accounts/[id]` — disconnects, revokes OAuth grants
- `POST /api/email/accounts/[id]/test` — sends to the signed-in user
- `POST /api/email/oauth/start` `{ presetId, scope, reconnectAccountId? }` → `{ authorizationUrl }`
- `GET /api/email/oauth/callback` → redirects to `/settings/email?connected=<id>` or `?error=<code>`
- `PUT /api/email/preference` `{ accountId: string | null }`
- `GET /api/email/deliveries?cursor=` → `{ deliveries: DeliveryView[], nextCursor }`
- `POST /api/email/deliveries/[id]/retry`
- `GET /api/email/templates`, `PUT /api/email/templates` `{ kind, subject, intro }`

```ts
type ProviderOption = {
  id: "gmail" | "google_workspace" | "microsoft365" | "outlook" | "zoho"
    | "yahoo" | "icloud" | "smtp" | "resend";
  name: string; method: "oauth" | "smtp" | "api";
  available: boolean; unavailableReason: string | null;
  appPasswordRequired: boolean; helpUrl: string | null;
  smtpDefaults: { host: string; port: number; security: "tls" | "starttls" } | null;
};
type EmailAccountView = {
  id: string; scope: "organization" | "personal"; ownedByMe: boolean;
  provider: "gmail" | "microsoft" | "smtp" | "resend"; presetId: ProviderOption["id"];
  emailAddress: string; displayName: string | null; replyTo: string | null;
  status: "connected" | "needs_reconnect" | "error"; isDefault: boolean;
  sharedWith: "nobody" | "everyone" | "teams"; teamIds: string[];
  lastSuccessAt: number | null; lastError: string | null; lastErrorAt: number | null;
  smtp: { host: string; port: number; security: "tls" | "starttls"; username: string } | null;
  createdAt: number;
};
type DeliveryView = {
  id: string; template: string; stream: "platform" | "agreement";
  toAddress: string; subject: string; envelopeId: string | null;
  status: "sent" | "failed" | "retrying" | "deferred" | "superseded";
  attempts: number; lastError: string | null; recovery: string | null;
  accountEmail: string | null; provider: string | null;
  createdAt: number; sentAt: number | null;
};
```

No response ever contains a password, API key, access or refresh token.

## 5. Settings (UI specialist)

`/settings/[section]` with sections `profile`, `workspace`, `team`,
`email`, `branding`, `documents`, `notifications`, `security`, `data`,
`advanced`. `/settings` opens `profile`. A search box filters a static index
of settings and links to `section#anchor`. Old anchors
(`/settings#organization` and friends) keep working by redirecting.
Technical SMTP, DNS and custom-domain detail lives under Advanced.
